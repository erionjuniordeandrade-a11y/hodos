- **Structured data**: one `<script type="application/ld+json">` block on `index.html`
  (`@graph` of WebSite, Person, Course with `hasPart` = the ten lessons as LearningResource)
  and one on `atlas-sources.html` (Person + BreadcrumbList). No MedicalWebPage/MedicalEntity
  types used. Both blocks parse (`node -e` checked). **CSP note**: `scripts/build-hodos.mjs`
  had a blanket guard that threw on any inline `<script>` without `src=`, meant to force a CSP
  hash for anything executable. `application/ld+json` isn't a JavaScript/module/importmap MIME
  type, so CSP's `script-src` never restricts it — it's inert data, not code — so the guard now
  carves out that one `type` and still throws for anything else. `script-src` itself is
  unchanged (`'self'` + the importmap hash + `'wasm-unsafe-eval'`).
- **Favicons**: `viewer/favicon.ico` (32px) and `viewer/apple-touch-icon.png` (180px) generated
  from `brand/hodos-favicon.svg` via `rsvg-convert` (at `~/fsl/bin/rsvg-convert`) and `magick`.
  The SVG's own rounded-rect background is `#0f1215`, which is also `--color-paper` converted
  from `oklch(18% 0.008 248)` — computed by hand (Oklab → linear sRGB → sRGB, not a library) and
  confirmed identical to the existing `theme-color` meta. The favicon keeps that rounded corner
  transparency (normal for a 32px favicon); the apple-touch-icon was composited onto an opaque
  `#0f1215` square first, since iOS doesn't accept transparency. `viewer/site.webmanifest` was
  added (name, short_name, icons, theme/background color, `standalone`, `start_url: /`). All
  four HTML pages link `favicon.ico`, `brand/hodos-favicon.svg`, `apple-touch-icon.png` and
  `site.webmanifest`; the build allowlists and copies all three new root files.
- **Home page numerals**: removed the `01 / 02 / 03` kickers (and the now-empty `<span>`) before

- **Middle dots**: `atlas-sources.html`'s five citation paragraphs (surface/parcels,

- **Gate**: `tests/perf/hodos_publication.mjs` had the old literal home/atlas titles hard-coded;

## Owner action needed: www and pages.dev duplicates

`www.hodosatlas.com` and `hodos-atlas.pages.dev` both currently serve 200 alongside the apex.
**Do not add host-matching rules to `_redirects`** — Cloudflare Pages' `_redirects` parser is
known to mis-handle host-scoped rules (a prior incident here, see `feedback-cf-pages-redirects-host-rules-poison-parser.md`
in the owner's memory). This needs a Cloudflare **Redirect Rule** instead, which is a dashboard
object independent of the Pages build:

1. Cloudflare dashboard → the `hodosatlas.com` zone → **Rules → Redirect Rules → Create rule**.
2. Name it something like "www to apex".
3. **When incoming requests match**: Custom filter expression —
   `(http.host eq "www.hodosatlas.com")`.
4. **Then**: Dynamic redirect (not Static), so the path and query survive:
   - Type: Dynamic
   - Expression: `concat("https://hodosatlas.com", http.request.uri.path, if(http.request.uri.query != "", concat("?", http.request.uri.query), ""))`
   - Status code: **301** (permanent)
   - Preserve query string: on (redundant with the expression above, but leave it on)
5. Save and deploy the rule. Confirm with `curl -I https://www.hodosatlas.com/atlas?lesson=motor-cst`
   → expect `301` to `https://hodosatlas.com/atlas?lesson=motor-cst`.
6. `hodos-atlas.pages.dev` is a Pages project alias, not a DNS host you control the same way;
   leave it serving (Pages requires the `.pages.dev` domain to keep working for preview
   deploys) and let the canonical tag on every page (already `https://hodosatlas.com/...`) tell
   search engines which host is authoritative. No redirect rule is needed or safe to add for it
   here.

This step is dashboard-only and out of scope for this worktree; nothing in the export or
`_redirects` was changed to attempt it.
