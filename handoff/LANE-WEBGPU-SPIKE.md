# WebGPU feasibility spike — 2026-09-27

## Recommendation: NO-GO-FOR-NOW for a production atlas port

WebGPU rendering is feasible: the probe loaded the **landed meshopt cortex-L/R GLBs** and the actual `AF_L` range-loaded tract bundle, and both backend branches rendered in Chromium. This probe did **not** show a frame interval gain, while a real port would require rewriting the atlas post-processing and custom line shaders. Keep the current WebGL atlas and revisit after a representative full-scene prototype and Safari/iPad measurement.

This is a feasibility decision, not a conclusion that WebGPU is slower. The probe compares two backends of `WebGPURenderer`; it omits Hodos AO, parcel colouring, clipping, annotations, controls and effects. The frame interval was close to the browser's 120 Hz cadence; `meanRenderCallMs` measures CPU submission, not GPU execution.

## Probe and evidence

`output/webgpu-probe/index.html`, `probe.mjs`, and `probe.css` are outside the export allowlist and gitignored. Identical source plus `webgpu.png` and `webgl.png` are copied to `handoff/webgpu-probe/` for review. The HTML uses an import map for **three 0.186.1** from `output/webgpu-probe/node_modules/three/`; this package was extracted from the local npm cache into ignored output, without modifying the repository's `node_modules` symlink, package.json, viewer vendor, or build. The probe uses `MeshStandardNodeMaterial`, `three/addons/lines/webgpu/Line2.js` with `Line2NodeMaterial`, `viewer/atlas_data.js` `decodeAtlasBundle`, and `viewer/tract_ranges.js` `createTractRangeLoader`. It has a `?backend=webgl` `forceWebGL` branch. The result box and `window.__probe` contain the observed metrics.

The probe's CSP meta policy mirrors the generated export `_headers` policy (with the probe import-map hash). Both backends completed with **0 console errors and 0 warnings** in the automated browser. The two copied PNGs were rehashed against their ignored originals and each is **1280×800**. The actual export header remains generated by `scripts/build-hodos.mjs`; this spike made no shipping CSP change.

## Port blockers found in the live code

| Area | Evidence and required port work |
|---|---|
| AO and composite | `viewer/render_pipeline.js` uses GLSL `ShaderMaterial` for a depth-sampling AO pass and a colour × AO composite, `WebGLRenderTarget`, `DepthTexture`, WebGL2 capability checks, and three render passes. A WebGPU port needs equivalent TSL/node post-processing and visual parity checks. [three's migration guide](https://threejs.org/manual/pages/webgpurenderer) says `ShaderMaterial` and this style of post-processing are unsupported in `WebGPURenderer`. |
| Cortex/tract shader hooks | `viewer/atlas_scene.js` patches `LineMaterial.onBeforeCompile` and `customProgramCacheKey` to add front-facing and arc attributes, endpoint feather, and two moving pulses. `viewer/scene_materials.js` patches `onBeforeCompile` and `customProgramCacheKey` for the proximity sub-floor hatch. These GLSL hooks need TSL/node equivalents; the probe's plain WebGPU lines do not reproduce them. |
| Renderer assumptions | `viewer/atlas_scene.js` instantiates `WebGLRenderer`, sets `localClippingEnabled`, handles WebGL context lost/restored events, and passes renderer capabilities into `createRenderPipeline`. These code paths need an explicit backend-aware implementation and regression tests for reduced motion and presenter profile. |
| CSP / WGSL | The release `_headers` is built in `scripts/build-hodos.mjs`: `script-src 'self' <import-map hash> 'wasm-unsafe-eval' ...`, `connect-src 'self' ...`, `worker-src 'self' blob:`. The CSP-mirrored Chromium probe compiled and rendered WGSL without adding `'unsafe-eval'` or a new shader source. A shipping import map or new module must be allowlisted and hashed by the exporter. Safari's CSP behavior and any fetched external WGSL still need a live export test. The observation about WGSL is browser evidence, not a claim about every implementation. |
| Browser coverage | [WebKit states](https://webkit.org/blog/17333/webkit-features-in-safari-26-0/) WebGPU ships in Safari 26.0 on macOS, iOS and iPadOS. Older Safari/iPadOS versions still need WebGL fallback. Audience version distribution and physical iPad performance were not measured. [Three's guide](https://threejs.org/manual/pages/webgpurenderer) describes its fallback and says the renderer is still experimental. |
